# Mini NPU 시뮬레이터

MAC(Multiply-Accumulate) 연산으로 입력 패턴이 **십자가(Cross)** 인지 **X** 인지 판정하는 Python 콘솔 프로그램입니다.
외부 라이브러리(NumPy 등) 없이 반복문만으로 MAC 연산을 직접 구현했습니다.

## 실행 방법

```
python main.py
```

실행하면 모드를 선택합니다.

| 번호 | 모드 | 설명 |
|---|---|---|
| 1 | 사용자 입력 (3×3) | 필터 A, B와 패턴을 직접 입력 → 점수/판정/성능 출력 |
| 2 | data.json 분석 | 5×5, 13×13, 25×25 패턴을 일괄 채점 → PASS/FAIL, 성능 표, 결과 요약 출력 |

## 파일 구성

```
mini-npu/
├── main.py      # 프로그램 전체
├── data.json    # 필터와 테스트 패턴
└── README.md
```

## 주요 기능

- **MAC 연산** (`mac`): 패턴과 필터의 같은 위치 값을 곱해서 모두 더한 점수를 반환합니다.
- **판정** (`judge`): 두 점수 차이가 `1e-9`보다 작으면 `UNDECIDED`, 아니면 큰 쪽으로 판정합니다.
- **입력 검증** (`read_matrix`): 숫자 개수가 틀리거나 숫자가 아닌 값이 들어오면 안내 문구를 출력하고 그 줄을 다시 입력받습니다.
- **라벨 정규화** (`normalize_label`): `+`, `cross` → `Cross` / `x` → `X` 로 통일합니다.
- **스키마 검증**: 키에서 N을 추출해 `size_N` 필터를 고르고, 패턴 크기가 N×N이 아니면 프로그램을 멈추지 않고 FAIL로 기록합니다.
- **성능 측정** (`measure_time`): 크기별로 MAC 함수 호출 구간만 10회 측정해 평균(ms)을 냅니다.

```
[성능 분석] (각 크기별 10회 평균)

--------------------------------------

13×13     0.005940        169
25×25     0.020095        625

[결과 요약]
  전체 테스트: 13개
  통과: 12개
  실패: 1개
  실패 케이스:
    - size_13_5: 크기 불일치 (필터 13×13, 패턴 5줄)
```

## 결과 리포트

### 1. 실패 원인 분석

- 전체 13개 테스트 중 12개가 PASS, 1개가 FAIL입니다.
- 실패한 `size_13_5`는 키 이름은 13×13인데 실제 `input`은 5×5 배열입니다.
- 이는 MAC 로직이나 수치 비교 문제가 아니라 **데이터/스키마 문제**입니다.
- 크기를 검사하지 않고 그대로 MAC을 계산했다면 13×13 필터의 범위를 벗어나 `IndexError`로 프로그램이 멈췄을 것입니다.
- 그래서 MAC 계산 전에 `is_square`로 N×N인지 먼저 확인하고, 다르면 FAIL 사유를 남긴 뒤 다음 케이스로 넘어가도록 했습니다.
- 라벨 문제도 같은 종류의 스키마 문제입니다. data.json의 expected는 `+`/`x`, 필터 키는 `cross`/`x`로 표기가 서로 다릅니다.
- 이것을 그대로 비교하면 판정이 맞아도 `"Cross" != "+"`가 되어 FAIL이 나옵니다. 그래서 `normalize_label`로 모두 `Cross`/`X`로 통일한 뒤 비교했습니다.
- 나머지 12개가 모두 PASS가 된 이유는 (1) 라벨 정규화, (2) 크기 검증, (3) epsilon 비교 정책 덕분입니다.
- 부동소수점 문제: 컴퓨터에서 `0.1 + 0.2`는 정확히 `0.3`이 아니라 `0.30000000000000004`입니다.
- 필터나 패턴에 실수가 들어가면 같은 점수여야 할 두 값이 아주 조금 달라질 수 있으므로, `abs(a - b) < 1e-9`이면 동점(UNDECIDED)으로 처리하는 정책을 적용했습니다.
- 실패 진단 순서: ① 데이터/스키마(키 형식, 라벨, 크기) → ② 로직(MAC 계산, 판정 방향) → ③ 수치 비교(epsilon) 순으로 확인했습니다.

### 2. 시간 복잡도 분석

- MAC 연산은 N×N 배열의 모든 칸을 한 번씩 곱하고 더하므로 연산 횟수는 **N²** 입니다.
- 따라서 시간 복잡도는 **O(N²)** 입니다.
- 실제 측정에서도 N²에 비례하는 경향이 보입니다.
  - 5×5 → 25×25: 연산 횟수 25 → 625 (25배), 시간 약 0.0011ms → 0.0201ms (약 18배)
  - 13×13 → 25×25: 연산 횟수 169 → 625 (약 3.7배), 시간 약 0.0059ms → 0.0201ms (약 3.4배)
- 배수가 정확히 같지 않은 이유는 함수 호출, 반복문 준비 같은 고정 비용이 있고, 측정 시간이 매우 짧아 컴퓨터 상태에 따라 오차가 생기기 때문입니다.
- 한 변(N)이 2배가 되면 연산은 4배가 되므로, 실제 AI처럼 필터가 수백×수백이 되고 수천 개를 쓰면 연산량이 폭발적으로 늘어납니다.
- CPU는 이 곱셈·덧셈을 하나씩 순서대로 처리하지만, NPU는 많은 MAC 연산을 동시에(병렬로) 처리해서 이 문제를 해결합니다.
